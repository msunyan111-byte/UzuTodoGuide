# UZU Studio 併用画面・要件設計

## 1. 目的と前提

UZU Studio の編集画面を実際に使いながら、隣に置いて使える制作伴走アプリの画面と要件を定義する。

本アプリは UZU Studio の代替エディタではない。UZU Studio 上で「どの画面を、何のために、どこまで設定したか」を記録し、次にやることを示す。シナリオ本文、画像、音声、秘密情報の正本は UZU Studio 側に置く。

公式ガイドの日本語ページ79件を読み、機能・設定項目・制約・注意点を `doc/UZU_FEATURE_INVENTORY.md` に整理した。本書はそのインベントリを画面と要件に落とし込む。

- 公式ガイド: `https://docs.studio.uzu-app.com/`
- 公式インデックス: `https://docs.studio.uzu-app.com/llms.txt`
- 基本テンプレート: `https://docs.studio.uzu-app.com/overview/template/basic`
- 発展テンプレート: `https://docs.studio.uzu-app.com/overview/template/advanced`
- 機能インベントリ: `doc/UZU_FEATURE_INVENTORY.md`

基本／発展の画面別提供範囲は公式に一覧がない。本設計では公式テンプレート解説から推定し、画面に「推定」バッジを出せるようにする。

## 2. 設計原則

1. UZU Studio が正本。本アプリは進捗、短いメモ、確認日、判断の記録だけを持つ。
2. 機能別ではなく、UZU の画面・タブ・設定項目別にナビゲーションを揃える。
3. どの画面でも「次にやること」を1つ示す。
4. UZU と横並びにできるよう、狭い幅でも破綻しない。専用のコンパクトモードを用意する。
5. iframe 埋め込み、UZU への自動入力、API 同期は行わない。外部リンクは新しいタブで開く。
6. チェック未完了でも作業記録を妨げない。警告として表示する。
7. 公式ガイドの本文を大量複製しない。画面名、設定項目、制約、公式リンク、確認日を扱う。
8. 秘密情報やシナリオ本文を貼る場所にしない。メモにはその旨を明示する。
9. 制約は隠さない。PC上限、条件階層、画像容量、テスト回数などは、該当画面にそのまま表示する。
10. 公式情報の更新に備え、機能定義に確認日と「推定／確定」を持つ。

## 3. 併用時の画面構成

### 3.1 モニター別の使い方

| 環境 | 推奨レイアウト |
|---|---|
| 1920×1080 1画面 | 左に UZU Studio、右に本アプリのコンパクトモード（幅 360〜480px） |
| 1366×768 1画面 | 左に UZU Studio、右にコンパクトモード（幅 360〜420px）。UZU 側はブラウザーのズームを調整 |
| 2画面 | 1画面に UZU Studio、もう1画面に本アプリの通常モード |
| タブレット | UZU Studio は別タブ。本アプリは1カラム表示 |

### 3.2 画面の基本構成

通常モード（幅 1200px 以上）:

```text
+----------------------------------------------------------------------------+
| uzu-todo-guide   [作品名 v]   PAID / 制作中   12/46   [UZUを開く]  [検索] |
+--------------+--------------------------------+----------------------------+
| 全体ナビ     | UZU画面ナビ（グループ）        | メイン                     |
|              |                                |                            |
| ダッシュ     | ▼ 作品                         | キャラクター               |
| 作品         |   作品概要              4/4    | UZU: キャラクター > 基本   |
| UZUガイド    |   サブ画像              0/2    | 公式確認日: 2026-11-03     |
| 設定         |   ジャンル              1/1    | [基本] [推定]              |
|              | ▼ エディタ                     |                            |
|              |   キャラクター          2/8    | 次にやること               |
|              |   フェーズ              1/9    | ミッションを設定する       |
|              |   フェーズ進行          0/4    |                            |
|              |   テキスト              0/3    | 制約                       |
|              |   手がかり              2/5    | PC最大8 / NPC無制限        |
|              |   山札                  0/2    | 条件は最大3階層            |
|              |   ルーム                0/2    |                            |
|              |   トークン              0/2    | チェック項目               |
|              |   自由記述              0/2    | [ ] 基本項目               |
|              |   トリガー              0/2    | [ ] ミッション             |
|              |   アクション            0/3    | [ ] 条件付きアイコン       |
|              |   演出                  0/5    |                            |
|              |   条件                  0/3    | メモ                       |
|              |   画面デザイン          0/2    | [短いメモ________________] |
|              | ▼ 品質                         |                            |
|              |   動作確認 / バージョン / ...  |                            |
```

- 1200px 以上: 3カラム。
- 768〜1199px: 全体ナビをアイコン＋短縮ラベルにし、UZU画面ナビとメインの2カラム。
- 767px 以下: 1カラム。UZU画面ナビは上部の選択メニューにする。
- コンパクトモード: 全体ナビとUZU画面ナビを隠し、次にやること中心の専用表示にする。
- 39セクションを一度に並べない。グループを折りたたみ、検索と「よく使う」を持つ。

### 5.2 ナビゲーションの見せ方

- 39セクションをフラットに並べない。グループ（アカウント、作品、エディタ、品質、感想戦、発展、共通）で折りたたむ。
- 作品ワークスペースでは「作品」「エディタ」「品質」を既定で展開し、それ以外は必要時に開く。
- 「よく使う」に最大6件をピン留めできる。既定は作品概要、キャラクター、フェーズ、テキスト、動作確認、テストプレイ。
- セクション名の横に UZU 画面名を小さく表示する。UZU 上の名称と本アプリの名称が異なる場合はツールチップで補足する。
- `CHARACTERS` は基本テンプレートでも表示する。基本テンプレートにもプレイアブルキャラクターの入力があるため。発展では NPC 追加、PC 追加、種別、条件付きアイコンなどが増える。
- 投票は独立セクションにせず、`PHASES` 内の「投票ボックス」として扱う。公式ガイド内で「投票フェーズ」と「基本フェーズ内の投票ボックス」の表現が揺れているため、現行UIを確認して表示する。

## 7. 画面設計

### 7.1 SCR-01 ダッシュボード

```text
+--------------------------------------------------------------------------+
| uzu-todo-guide                                       [作品を追加] [設定] |
+--------------------------------------------------------------------------+
| 続きから                                                                 |
| 吸血鬼の館のマーダーミステリー                     PAID / 制作中  12/46   |
| 次にやること: キャラクターの「ミッション」を設定する                     |
| [ワークスペースを開く]  [UZUを開く]                                      |
+--------------------------------------------------------------------------+
| 作品                                                                     |
| +----------------------+ +----------------------+ +----------------------+|
| | 吸血鬼の館...        | | 夜明けの証言         | | 砂の記憶             | |
| | 制作中  12/46        | | テストプレイ 24/46   | | 企画  2/46           | |
| | 次: ミッション       | | 次: アンケート回収   | | 次: あらすじ         | |
| +----------------------+ +----------------------+ +----------------------+|
+--------------------------------------------------------------------------+
| 公開準備の注意                                                           |
| - 有料作品のテストプレイが UZU 1回を含む3回に届いていません             |
| - 売上受取人の規約同意が未確認です                                       |
| - 画像の容量超過候補が2件あります                                        |
+--------------------------------------------------------------------------+
```

- 続きから: 最終更新が最も新しい未アーカイブ作品。次アクションと UZU リンク。
- 作品カード: タイトル、公開形態、制作段階、進捗、次アクション、最終更新。
- 注意: 期限超過、有料テスト要件、規約同意、未対応の審査指摘、素材制約、長期間更新なし。
- 空状態: 作品新規作成と UZU 新規作成画面への導線。

次アクションの決定順:

1. 期限を過ぎた未完了の Must チェック項目。
2. 制作段階に対応するセクションの未完了項目。
3. 公開準備の必須条件（テスト、審査、同意、素材）。
4. 未完了の Should 項目。
5. すべて完了なら「バックアップを確認する」。

- 既定は未アーカイブ、更新日時の降順。
- 状態、公開形態、テンプレート、アーカイブ有無、外国語版有無で絞り込む。
- カード表示とテーブル表示を切り替えられる。既定はカード。
- アーカイブ済みはバッジを付け、編集操作を無効化する。

### 7.3 SCR-03 作品ワークスペース

セクション詳細の構成:

1. パンくず: `作品 > UZU画面 > 項目`。
2. 状態: 未着手／対応中／完了。未完了項目数から自動算出。
3. UZU リンク: 該当画面を開く。画面名をコピーするボタンを併設。
4. 公式確認日: 機能定義の確認日。古い場合は「公式を確認」を表示。
5. 基本／発展バッジ: 推定の場合は「推定」を付ける。
6. 次にやること: そのセクションの最初の未完了項目。
7. 制約: PC最大8、条件3階層、画像4.5MBなど、該当する制約をチップ表示。
8. チェック項目: UZU の項目単位。状態、メモ、期限、公式リンク。項目名の先頭には UZU Studio の画面名を【】付きで付け、説明には操作手順と完了条件を含める。
9. 項目カバレッジ: 作品概要、キャラクター、フェーズなど、項目の多い画面で表示。
10. メモ: 2000文字以内のプレーンテキスト。自動保存。
11. 最終確認日: 「UZU上で確認した」ボタンを押した日時。
12. 関連機能: 同じ制約や依存関係を持つ機能へのリンク。

セクションの並びは UZU の画面に合わせる。基本テンプレートでもキャラクターは表示する。発展テンプレートでは NPC 追加、種別、条件付きアイコン、トークン、トリガー、アクション、条件、画面デザインなどが追加される。

### 7.6 SCR-06 テストプレイ

- 実施日、UZU／UZU外、参加人数、対象バージョン、アンケート有無、URL、気づき、メモ。
- 合計回数と UZU 回数を分けて表示する。
- 有料作品は「UZU 1回以上を含む合計3回以上」の警告を出す。未達でも記録は妨げない。
- 参加条件（既プレイ可否など）をメモできる。
- ワークスペースの「テストプレイ」「バージョン」「動作確認」から遷移できる。

### 7.7 SCR-07 審査・公開準備

- 審査種別（簡易／詳細）、提出日、状態、結果、メモ。
- 指摘事項ごとに内容、対応状態、対応メモ。
- 公開希望日、料金、セール、告知メモ。
- 簡易は約3営業日、詳細は約5営業日を目安として表示する。日数は保証ではない。
- 詳細審査の結果は「審査通過」「修正して再提出」「クオリティ不足」。
- 有料審査通過後に無料公開できないことを警告する。
- リリース日時と6時間ルールを確認する。
- 審査中でも作品情報を編集できる。提出時点の内容を固定したと誤認させない。

### 7.8 SCR-08 設定・バックアップ

- JSON エクスポート、復元、最終バックアップ日時。
- 復元前の確認、形式検証、失敗時に既存データを壊さない注意。
- 公式ガイドの確認日一覧。
- アプリの表示設定（通常／コンパクト、文字サイズ、グループの開閉状態）。
- 機能定義の「推定」一覧と、公式確認待ちの項目。

## 12. 画面状態

| 状態 | 表示 |
|---|---|
| 初回起動 | 作品新規作成と UZU 新規作成画面への導線 |
| 作品なし | 空状態。サンプル作品の案内は任意 |
| 読み込み中 | スケルトン。レイアウトシフトを抑える |
| 通信エラー | 再試行ボタンと、未保存の可能性の注意 |
| 保存中 | ヘッダーに「保存中」、完了後に「保存済み」 |
| 保存失敗 | 入力内容を保持し、再試行を促す |
| アーカイブ済み | 読み取り専用バナー。編集ボタンを無効化 |
| 未完了あり | 警告表示のみ。操作は禁止しない |
| 公式ガイド未確認 | 確認日が古い場合に「公式を確認」を促す |
| 推定情報 | 「推定」バッジと、現行UI確認の案内 |
| 制約超過 | 画像容量、PC数、条件階層などの警告 |

## 13. 非機能要件

- ローカルPCのブラウザーから利用する。認証、共同編集、外部公開は対象外。
- 既定は `127.0.0.1` バインド。外部ネットワークへ公開しない。
- 画面遷移と保存はローカル環境で体感上待たせない。目標は初回表示1秒以内、操作応答200ms以内。
- 最新の Chrome、Edge、Firefox を対象とする。Safari は Should。
- 日本語の文字切れ、長い作品名、長いメモでレイアウトが崩れない。
- 画像・音声・動画は保存しない。UZU 側の素材を参照するリンクやメモのみ扱う。
- アクセシビリティは WCAG 2.1 AA を目標に、コントラスト、フォーカス、キーボード操作、タップ領域を確保する。
- アニメーションを減らす設定に従う。
- 外部アクセスは利用者がリンクを押した場合のみ。分析、トラッキング、外部フォントの自動取得は行わない。
- 参照データの確認日を表示し、古い情報で断定しない。

## 14. 実装方針

- フロントエンドは `frontend/` の React 18 + TypeScript + Vite 6 とする。開発時は `/api` を Spring Boot の `8080` へ proxy し、`npm run build` で `src/main/resources/static` へ出力する。
- 画面遷移は Hash Router とし、Spring Boot の静的配信でもリロード時に 404 にならないようにする。
- 既存の `/api/v1` を fetch で利用する。作品・チェックリスト・作品編集・バックアップ・復元は API、セクションの短いメモと最終確認日は `localStorage` に保存する。
- サーバー側は画面用の集約APIを追加し、UI から複数APIを順番に呼ばないようにする。現状は作品一覧時に各作品のチェックリストを並列取得しているため、件数増加時は `/workspace` 集約APIへ置き換える。
- UZU のセクション・機能定義は `frontend/src/data/uzu.ts` で管理し、公式ページの変更時は確認日とともに更新する。
- API に接続できない場合はデモデータを表示し、UI の確認とデザイン検討を継続できるようにする。デモ中の編集は永続化しない。
- UZU への深いリンクが提供されていない場合は、`https://studio.uzu-app.com/` を開いたうえで、画面名をコピーして手動で移動できるようにする。
- 39セクションはグループ折りたたみと検索で扱い、初期表示で圧迫しない。
- 現時点の実装範囲は Phase 1〜2 と、Phase 3 の一部（機能ガイド、公開準備チェック、発展セクション表示）。テストプレイ記録・審査記録の専用画面、セクション別のサーバー保存、集約APIは未実装。

## 15. MVP の分割

| フェーズ | 内容 |
|---|---|
| Phase 1 | ダッシュボード、作品一覧、ワークスペース、UZU機能ガイド、コンパクトモードの基本 |
| Phase 2 | セクション別チェック、次アクションの理由、最終確認日、作品概要・キャラクター・フェーズのカバレッジ |

| Phase 4 | 有料運用（規約、売上、追加コンテンツ、チケット）、外国語版、v1→v2移行、素材チェック |
| Phase 5 | 検索、キーボード操作、表示設定、履歴、バックアップ確認 |

## 16. 受け入れ条件

1. 作品ワークスペースで UZU の画面名と本アプリのセクションが対応して表示される。
2. 39セクションがグループ化され、検索と折りたたみで扱える。
3. 各セクションから公式ページを新しいタブで開ける。
4. ダッシュボードとワークスペースに次にやることが1つ表示される。
5. セクションの進捗がチェック項目の完了数と一致する。
6. 基本テンプレートでもキャラクターが表示され、発展テンプレートでは NPC 追加などが表示される。
7. 投票が基本フェーズ内の投票ボックスとして説明される。
8. UZU機能ガイドで制約（PC上限、条件階層、容量、回数）を確認できる。
9. コンパクトモードが幅360pxで横スクロールなしに操作できる。
10. UZU Studio を iframe で埋め込んでいない。
11. メモと最終確認日時が保存され、バックアップに含まれる。
12. チェック未完了でもテストプレイと審査の記録ができる。
13. アーカイブ済み作品は閲覧のみとなる。
14. 公式情報の確認日と「推定／確定」が表示される。
15. 有料作品のテスト、規約同意、審査、素材、リリース条件が公開準備チェックに表示される。

## 17. 検証・未決事項

- 基本テンプレートと発展テンプレートの画面別提供範囲。公式に一覧がないため、現行UIで確認する。
- 投票が「基本フェーズ内の投票ボックス」か「独立した投票フェーズ」か。公式ガイド内で表現が揺れている。
- UZU Studio の画面単位の深いリンクが利用できるか。現案はトップページ＋画面名コピー。
- 39セクションが多すぎないか。グループ折りたたみで運用し、必要なら統合する。
- セクションごとのメモに、シナリオ本文の下書きをどこまで許可するか。現案は短いメモのみ。
- 機能定義をコード内 enum にするか、JSON リソースにするか。
- 公開準備チェックを既存チェックリストで表現するか、専用テーブルを持つか。
- セール、チケット、分配の最新運用。公式ガイド記載時点の情報であり、変更可能性がある。
- 外国語版、v1→v2移行を MVP に含めるか、Phase 4 以降にするか。
