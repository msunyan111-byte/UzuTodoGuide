# UZU Studio 機能インベントリ

## 1. 文書の目的

UZU Studio 公式ガイドの日本語ページ全79件を読み、制作伴走アプリの画面・チェックリスト・要件に必要な機能を整理したもの。公式本文の転載ではなく、制作時に確認すべき項目、制約、注意点の要約である。

- 正本: `https://docs.studio.uzu-app.com/`
- インデックス: `https://docs.studio.uzu-app.com/llms.txt`
- 対象: 日本語ページ79件（英語・繁体字中文は対象外）
- 読み取り日: 2026-11-03
- UI設計: `doc/UZU_STUDIO_COMPANION_UI.md`

公式ガイドは更新される。重要な判断では必ずリンク先の最新情報を確認する。本文中の「基本」「発展」は公式テンプレート解説に基づくが、画面単位の厳密な提供範囲は公式に一覧がないため、推定を含む。

| 機能 | 内容 | 制作側の確認事項 |
|---|---|---|
| 作家プロフィール | プレイヤー名とは別に作家名、カバー画像、アイコン、紹介、リンクを設定 | 作品概要の作者表示と一致しているか |
| 規約同意 | 有料公開・有料追加コンテンツでは売上受取人全員の同意が必要 | 共同制作者がいる場合、全員が同意済みか |

## 6. フェーズ

### 6.1 フェーズ共通

| 機能 | 内容 | 制約・注意 |
|---|---|---|
| フェーズ追加 | 基本、読み合わせ、ゲームの流れ表示、投票、探索、複合 | 画面や時期により選択肢が異なる。現行UIを確認 |
| 基本フェーズ項目 | 管理タイトル、タイトル（必須）、サブタイトル、キャプション、所要時間、フェーズ完了条件、次へを押せるキャラクター、フェーズ内容 | 管理タイトルはアプリ非表示。所要時間は「次へ」なら目安、「タイマー」なら設定時間 |
| フェーズ内容 | テキスト、画像、山札、アクション、投票 | 画像は寄せ・大きさを設定。文字装飾あり |
| フェーズ内容の記録 | テキストとして配布、このフェーズのコピー | 同期テキストはテキスト側で編集不可。コピーは編集可 |
| フェーズ進行 | 基本遷移1本＋条件遷移、優先順位 | 全条件遷移は不可。上から優先。記号はIDのみ |
| ゲームの流れ表示 | 制限時間、表示内容、先フェーズの隠蔽 | 時間はフェーズ側と流れ側の両方に入力 |

出典: `basic-features/phase.md`, `phase/basic.md`, `phase/basic/discussion.md`, `phase/flow.md`

### 6.2 フェーズ種別

| 種別 | 用途 | 主な設定 | 注意 |
|---|---|---|---|
| 基本 | テキスト読込、追加情報、議論、説明、調査 | タイトル、サブタイトル、キャプション、所要時間、完了条件、内容 | 投票は基本フェーズ内の投票ボックス |
| 読み合わせ | セリフ・地の文・画像・BGMで台本進行 | セリフ、話者、地の文、画像、BGM切替 | 画像はセリフ右の操作から挿入。スキップ設定あり |
| ゲームの流れ表示 | 全体像と次フェーズを表示 | 制限時間、表示内容、先フェーズ隠蔽 | フェーズ側と時間を二重入力 |
| 投票 | 犯人投票、行動選択、調査 | 選択肢、画像、表示条件、投票条件、投票者、閲覧者、複数票、結果表示 | 2024/10以降は基本フェーズ内の投票ボックス。テンプレート上の「投票」追加との差異は現行UIを確認 |
| 探索（キャンバス） | 画像タップで自由調査・移動 | 背景、タイトルカード、オブジェクト、非活性表示、重なり、背景切替で移動 | 前半の調査を後半に再利用するか確認 |
| 複合 | 複数種の統合 | 種別の組み合わせ | 2026/3追加。現行UIを確認 |

出典: `phase/basic/*.md`, `overview/template/advanced.md`

### 6.3 投票の詳細

- 選択肢ごとに画像を設定できる。
- 表示条件: 条件を満たさない選択肢は全キャラクターに完全非表示。
- 投票条件: 特定条件・特定キャラクターのみ投票可。投票不可は薄色表示。
- 投票できるキャラクター、投票内容を閲覧できるキャラクターを設定できる。
- 同じ選択肢に2人以上投票できない設定がある。調査フェーズと相性が良い。
- 1人に複数票、条件を満たすキャラクターだけ複数票を持たせる設定ができる。
- 1フェーズに2つ以上の投票を置く場合は、何の投票かテキストで明示する。
- 投票結果は基本フェーズ、テキスト、手がかり、感想戦に置ける。投票前でも表示されるため、表示条件で制御する。
- フェーズ完了条件が「次へ」なら未投票で進めない。「制限時間」なら未投票でも進む。

出典: `basic-features/phase/basic/select.md`

## 7. テキスト・手がかり・山札

### 7.1 テキスト

| 機能 | 内容 | 注意 |
|---|---|---|
| テキスト追加 | テキストグループ、タイトル、本文 | 入力消失時はリロードで復旧することがある |
| 配布条件 | 条件を満たすキャラクターに配布 | フェーズ内容の記録はフェーズ終了時に配布 |
| 読み返し | テキストタブで後から閲覧 | 配布タイミングと閲覧条件を確認 |
| フェーズ内容の配布 | 同期テキスト／コピーテキスト | 同期はテキスト側で編集不可 |
| 文字装飾 | 色、太字など | 色変更が反映されない時はリロード。黒に戻すのは「Tx」 |
| 空テキスト | 空のテキストボックス | 「エラーが発生しました」の原因になる |

出典: `basic-features/texttab.md`, `basic-features/phase/basic/discussion.md`

### 7.2 手がかり

| 機能 | 内容 | 注意 |
|---|---|---|
| 基本 | 画像、本文、タグ、公開条件、配布先 | 一覧は正方形、詳細は16:9 |
| タグ | 手がかりを分類・絞り込み | タグ設計を先に決める |
| 公開条件 | 条件を満たすと公開 | フェーズ・所持品・トークンなどと組み合わせ |
| 配布先 | 全員、特定キャラクター、山札など | 配布先の重複に注意 |
| 未公開の存在表示 | 未所持者に見せるか | 見えるのは非公開時タイトル＋タグのみ |
| 回収 | 一度配布した手がかりを回収 | 回収後の再配布条件を確認 |
| 譲渡 | キャラクター間で譲渡 | 譲渡可能なカードか確認 |
| キャラクター別内容 | 同じ手がかりでも表示内容を変える | 条件と表示の対応を確認 |
| アクション | 手がかり取得などのアクション | アクションと配布の二重設定に注意 |
| ポップアップ表示 | 取得時に画面へ表示 | 表示条件・タイミングを確認 |

出典: `basic-features/clue.md`

### 7.3 山札・トークン

| 機能 | 内容 | 注意 |
|---|---|---|
| 山札作成 | デッキ、カード、枚数 | カードの重複・不足に注意 |
| トークン | 山札を引くための消費トークン | トークンは状態変数としても使える |
| 複数トークン | 1デッキに複数トークンを設定 | 2025/7対応。消費数・所持数表示は既定ON |
| 引くタイミング | フェーズ・アクション・条件から引く | 引きすぎ・引き忘れを確認 |
| 強制公開 | 条件でカードを強制公開 | 公開順と情報量を確認 |
| ランダム配布 | 山札からランダムに配布 | 人数・枚数の整合性 |
| トークン比較 | 数値比較、条件参照 | 条件式の階層上限に注意 |

出典: `basic-features/decks.md`, `basic-features/token.md`

### 9.2 トリガー

| 機能 | 内容 | 注意 |
|---|---|---|
| 新規作成 | 発火条件と対象アクションを設定 | 条件の組み合わせ |
| フェーズ開始時 | 自動ミュートなど | 自動でミュート解除されないため通知＋SE推奨 |
| フェーズ遷移 | 条件で別フェーズへ | 遷移ループに注意 |
| 遅延発火 | フェーズ開始から一定時間後 | タイマーとの競合 |

出典: `basic-features/trigger.md`

### 9.3 条件設定

- 条件の種類: 数値カウント、年齢、誰々、誰でも、キャラクターグループなど。
- AND / OR を組み合わせられる。
- 入れ子は最大3階層。
- 同票最多／単独最多の条件がある。
- フェーズ、手がかり、トークン、キャラクター、投票結果などを参照できる。
- 条件付きアイコン、条件付きルーム名、選択肢の表示条件・投票条件は「上から優先」。

出典: `basic-features/condition.md`

## 15. 文章・運用の注意

- 補助動詞、こと、ときはひらがく。ダッシュは `――`、省略は `……`、`！？` の後は空白、句読点、行頭インデント、表記統一に注意。
- 推奨環境: Windows 11 + Chrome/Edge、macOS Sonoma 14 + Chrome/Safari。スマートフォンは動作するが非推奨。
- 画像アップロード不調は容量超過かリロード。改善しなければ運営へ。
- 「undefinedのフェーズ」は運営対応が必要。
- 入力消失、色変更不反映はリロードで復旧することがある。触ると復活不可の可能性。
- 空のテキストボックスはエラーの原因。
- 動作確認はChromeの自動再生制限に注意。Safariまたはautoplay許可で確認。
- 有料作品はテストプレイ3回以上、うちUZU1回以上、アンケート提出が必要。
- 審査通過後の無料公開は不可。無料から有料化は個別相談。
- 更新適用は6時間ルール。リリースは明示操作。
- v1→v2移行は「v1でアプリに反映」→「v2で復元」→レイアウト修正→動作確認→最新版作成→移行申請→承認→リリース。承認前リリース不可。v2からv1へ戻すことは不可。

出典: `overview/makingflow/submit/common-mistake.md`, `qanda/qanda.md`, `others/v1-v2.md`, `qanda/qanda-v1-v2.md`, `overview/available.md`

## 16. 伴走アプリのチェックリストへの反映方針

1. UZU の全機能を「画面」「設定項目」「制約」「確認観点」の4つで保持する。
2. 作品ごとのチェックリストは、UZU のセクションキーと機能キーに紐づける。
3. 公式に制約が明記されているものは Must の確認項目にする。
4. 公式に推奨・注意のみのものは Should の確認項目にする。
5. テンプレートの基本／発展は推定フラグを持ち、公式に確定できるまで「推定」と表示する。
6. 公式ガイドの確認日と更新履歴を持ち、古い情報で判断しないようにする。
7. 有料公開、外国語版、v1→v2移行は、通常制作とは別のチェックリストグループにする。
8. 画像・音声・動画の容量、形式、サイズは作品共通の「素材」セクションで確認する。
9. テストプレイ、審査、リリース、レポートは時系列の別セクションにする。
10. マーケティング、メンバー、エディション、コレクション、売上は公開前後の運用セクションとして分離する。
